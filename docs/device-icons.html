How they are made and matched

Generated from one set of outlines, keyed on the model name the player reports.

One projection

Each device is a front face and the depth it stands in, folded back up and to the right along one shared vector. Only the edges you could actually see are stroked, so the whole set shares a horizon. Within a family the real lengths survive, compressed: an Arc fills the tile, a Ray sits at four fifths of it.

Where the name comes from

The bridge reads each player's modelName from its device description, folds it down to lower-case words, then tests the keys under each glyph longest-first on word boundaries — so one sl is never caught by one.

A room that is two speakers

A bonded stereo pair reports both players in its ChannelMapSet, one on each channel. Those rooms are drawn as two smaller copies side by side; a room with a bonded sub is not a pair and keeps its single drawing.

Nothing matches

New hardware, a SYMFONISK, or a player that never answered its description gets the plain cabinet with a driver. A zone is never left without an icon.

Getting them to Audirvana

UPnP wants PNG in iconList, so each drawing is stroked into one at 48, 120, 240 and 512 px and served from /dev/{uuid}/icon/{fingerprint}/{size}.png — the fingerprint changes with the drawing, so a cached icon can never go stale. The same outline is also served as vector art at /dev/{uuid}/icon.svg.

At 48 px the line work holds. Below about 24 px a hairline starts to break up, so the raster uses a slightly heavier stroke than the default on this page.
