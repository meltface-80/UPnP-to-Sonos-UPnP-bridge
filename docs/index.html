Play to Sonos from Audirvana

Audirvana streams happily to any standard UPnP/DLNA renderer — but not to Sonos, whose players advertise themselves as ZonePlayer devices and expect their own dialect of UPnP. This bridge sits on your network and re-presents every Sonos room as an ordinary MediaRenderer, so your rooms simply show up in Audirvana's device list under their own names.

What it does

One container, one virtual renderer per Sonos room.

The bridge finds your players over SSDP, reads the household layout from Sonos’ own zone topology, and advertises one clean MediaRenderer:1 device per visible room — each carrying the room name you gave it in the Sonos app. Bonded subs, surrounds and BOOST/BRIDGE units are left out, because they are not rooms you play to.

When Audirvana starts a track, the bridge rewrites the metadata into the shape Sonos insists on and loads it through the player’s queue, so the next track Audirvana hands over plays gaplessly. Transport commands follow the group coordinator, so playing to a grouped room plays to the whole group; volume stays with the individual speaker. Audio never passes through the bridge — Sonos fetches it straight from Audirvana’s own HTTP server.

Install

Run it on any always-on Linux machine on the same network as your Sonos gear — a NAS, a Raspberry Pi, a home server. 

# Run the bridge (host networking is required for UPnP discovery)
docker run -d \
  --name sonos-upnp-bridge \
  --network host \
  --restart unless-stopped \
  ghcr.io/meltface-80/sonos-upnp-bridge:latest

That is the whole installation. Within a few seconds the bridge has found your players; open http://<host-ip>:1500/ to see which rooms it is publishing.

  1. Start the container on a Linux host on the same subnet as your speakers.
  2. Open Audirvana and go to its audio device list.
  3. Your Sonos rooms appear as Kitchen (Sonos), Study (Sonos) and so on. Pick one and play.
Host networking matters. UPnP discovery is multicast, and multicast does not cross Docker’s default bridge network. --network host is what lets the bridge see your Sonos players and lets Audirvana see the bridge. Docker Desktop on macOS and Windows does not provide real host networking, so run the container on Linux.

Configuration

Everything is optional. Pass any of these with -e NAME=value.

VariableDefaultWhat it does
NAME_SUFFIX" (Sonos)" Appended to each room name in Audirvana. Set to empty for bare room names.
HTTP_PORT1500 Port for the bridge’s device descriptions, control endpoints and status page.
SONOS_HOSTS— Comma-separated player IPs to use when multicast discovery is unreliable. One is enough.
INCLUDE_ZONES— Only publish these rooms, e.g. Kitchen,Study.
EXCLUDE_ZONES— Publish everything except these rooms.
BRIDGE_MODEqueue queue uses the Sonos queue for gapless playback; direct loads each track straight onto the transport.
UNGROUP_ON_PLAYfalse Detach a room from its Sonos group before playing to it, instead of playing to the whole group.
BRIDGE_IPauto Address to advertise, for hosts with several network interfaces.
LOG_LEVELINFO Set to DEBUG to log every UPnP action in both directions.

Good to know

Which formats will actually play?

Sonos accepts FLAC, ALAC, WAV, AIFF, MP3, AAC and Ogg over HTTP, up to 24-bit/48 kHz on current S2 hardware. It does not play DSD, and higher sample rates will be refused by the player. Set Audirvana’s maximum sample rate for the device accordingly — the bridge advertises the formats but cannot resample.

No rooms are showing up

Open http://<host-ip>:1500/. If the table is empty the bridge has not found your players: confirm the container really is on host networking, that the host shares a subnet with the speakers, and that nothing else on the host already holds UDP 1900. Setting SONOS_HOSTS to one player’s IP bypasses discovery entirely.

Rooms show up in the bridge but not in Audirvana

That is the second half of the same multicast path. Audirvana must be on the same subnet, and some routers and access points filter multicast between wired and wireless clients — look for an IGMP snooping or “multicast enhancement” setting. Restarting Audirvana forces a fresh search.

Playing to a grouped room plays everywhere

That is how Sonos groups work: transport commands belong to the group coordinator. Either ungroup the room in the Sonos app, or start the bridge with UNGROUP_ON_PLAY=true to have it detach the room automatically.
