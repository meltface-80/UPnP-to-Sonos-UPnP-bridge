Sonos Bridge

Play to Sonos from Audirvana

Audirvana streams happily to any standard UPnP/DLNA renderer — but not to Sonos, whose players advertise themselves as ZonePlayer devices and expect their own dialect of UPnP. This bridge sits on your network and re-presents every Sonos room as an ordinary MediaRenderer, so your rooms simply show up in Audirvana's device list under their own names.

How it works

One container, one virtual renderer per Sonos room — named after the room you named in the Sonos app.

Only control messages take that path. Audio never passes through the bridge — Sonos fetches it straight from Audirvana's own HTTP server, so there is no extra hop and no transcoding.

🔎Finds every room

Discovers your players over SSDP, then reads the whole household from Sonos' own zone topology — room names, addresses and grouping. Bonded subs, surrounds and BOOST/BRIDGE units are left out, because they are not rooms you play to.

🏷Metadata Sonos accepts

Sonos rejects third-party items whose DIDL-Lite lacks its own descriptor, and dislikes several protocolInfo forms that are perfectly legal UPnP. Incoming metadata is parsed and re-emitted in the shape the player wants.

⏭Gapless playback

Tracks are loaded through the Sonos queue, which is what makes gapless work. The follow-up calls Audirvana makes after a track change are recognised, so playback is never restarted mid-album.

🔊Group-aware transport

Transport commands follow the group coordinator, so playing to a grouped room plays to the whole group — the way Sonos behaves. Volume and mute stay with the individual speaker.

📡Live state

The bridge subscribes to each player's events and republishes them as standard LastChange events, so Audirvana's transport display stays in sync — with a periodic reconcile as a safety net.

🖼Icons per model

Each room carries a line drawing of the speaker it actually runs on — an Arc, a Sub, an Era 100 — drawn from the model name the player reports, and a bonded stereo pair is drawn as two speakers. The status page shows the same icons.

🆔Stable devices

Each room's UPnP identity is derived from the player's serial number, so Audirvana remembers your devices across bridge restarts and reinstalls instead of collecting duplicates.

Install with Docker

Run it on any always-on Linux machine on the same network as your Sonos gear — a NAS, a Raspberry Pi, a home server. There is nothing to configure.

No Docker yet? On DietPi run dietpi-software install 162 — 162 is its own Docker package, and the right way to install it there. On Debian, Ubuntu or Raspberry Pi OS, curl -fsSL https://get.docker.com | sh. If a DietPi install complains about missing kernel modules, reboot first and run it again.
# Host networking is required — UPnP discovery is multicast
docker run -d \
  --name sonos-upnp-bridge \
  --network host \
  --restart unless-stopped \
  ghcr.io/meltface-80/sonos-upnp-bridge:latest

That is the whole installation. Within a few seconds the bridge has found your players — open http://<host-ip>:1500/ to see which rooms it is publishing. If your user isn't in the docker group, prefix the command with sudo.

Host networking matters. UPnP discovery is multicast, and multicast does not cross Docker's default bridge network. --network host is what lets the bridge see your Sonos players and lets Audirvana see the bridge. Docker Desktop on macOS and Windows does not provide real host networking, so run the container on Linux — Audirvana itself can stay on your Mac.

Environment variables

Everything is optional — the defaults are what most setups want. Pass any of these with -e NAME=value.

First run

The container is up — three steps and you're listening.

  1. Check the bridge found your speakers. Browse to http://<your-server-ip>:1500/. Every room it is publishing is listed there with its model, address and current transport state.
  2. Pick a room in Audirvana. Open the audio device list — your rooms appear as Kitchen (Sonos), Study (Sonos) and so on. Select one and play.
  3. Set the sample-rate ceiling. Sonos takes FLAC, ALAC, WAV, AIFF, MP3, AAC and Ogg up to 24-bit/48 kHz on current S2 hardware, and does not play DSD at all. Cap Audirvana's maximum sample rate for the device to match — the bridge advertises formats but cannot resample.

Troubleshooting

Start at http://<host-ip>:1500/ — it shows exactly what the bridge can see, which tells you which half of the path is broken.

Nothing listed

No rooms are showing up

The bridge has not found your players. Confirm the container really is on host networking, that the host shares a subnet with the speakers, and that nothing else on the host holds UDP 1900.

Setting SONOS_HOSTS to one player's IP address skips discovery entirely.

Bridge sees them

…but Audirvana doesn't

That is the second half of the same multicast path. Audirvana must be on the same subnet, and some routers and access points filter multicast between wired and wireless clients — look for an IGMP snooping or “multicast enhancement” setting.

Restarting Audirvana forces a fresh search.

Starts then stops

Playback drops out

Usually a format the player will not take. Run with LOG_LEVEL=DEBUG and look for UPnP error 714 (illegal MIME type) or 701, then lower the sample rate or change format in Audirvana.

DSD never plays; above 24-bit/48 kHz is refused by the speaker.

Too many speakers

One room plays everywhere

The room is grouped in the Sonos app, and transport commands belong to the group coordinator — so the whole group plays. That is how Sonos works.

Ungroup it in the Sonos app, or start the bridge with UNGROUP_ON_PLAY=true.
